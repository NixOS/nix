# Version 2 derivation "ATerm" format

This is the form of [version 2] derivations in the [derivation "ATerm" format](../derivation-aterm.md), whose [common productions](../derivation-aterm.md#common) it uses.

**Experimental feature**: [Version 2] derivations, and so this form, are experimental, and may change.

Version 2 derivations represent their [options](@docroot@/store/derivation/index.md#options) and the [*pass as file*](@docroot@/store/derivation/index.md#pass-as-file) flags of their environment variables directly, and so do the references in their strings:

```ebnf
derivation-v2 = 'DrvWithVersion("v2",' outputs-v2 "," input-drvs-v2 "," input-srcs ","
                platform "," builder-v2 "," args-v2 "," env-v2 "," options ")" ;
```

## Interpolated strings {#interpolated}

The [builder](@docroot@/store/derivation/index.md#builder), [arguments](@docroot@/store/derivation/index.md#args), and environment variable values of a version 2 derivation are not plain strings, but lists of *pieces*, each either literal text or a reference:

```ebnf
interpolated = list(piece) ;
piece        = string | reference ;
reference    = '("input",' deriving-path ")"
             | '("output",' output-name ")" ;

builder-v2   = interpolated ;
args-v2      = list(interpolated) ;
```

An `"input"` reference stands for the store path of a [deriving path](@docroot@/store/derivation/index.md#deriving-path), which must be one of the derivation's [inputs](@docroot@/store/derivation/index.md#inputs).
An `"output"` reference stands for the store path of the named output of the derivation itself.
When the derivation is [resolved](@docroot@/store/resolution.md) or built, each reference is replaced by the store path it stands for, and the pieces are concatenated.

So version 2 derivations never contain [placeholders](@docroot@/store/derivation/index.md#placeholders): where a version 1 derivation would have a placeholder, or a store path, a version 2 derivation has a reference.

> **Rationale**
>
> Placeholders encode a reference *inside* a string, so substituting them means searching every string for anything that looks like one, and replacing it.
> Literal text that happens to look like a placeholder or a store path is then rewritten too --- the same kind of mistake as an SQL injection, where data is mistaken for code.
> With references kept separate from literal text, nothing is ever searched for, and literal text is never mistaken for a reference.

Adjacent literal pieces are always merged, and a literal piece is never empty, so that each interpolated string has exactly one encoding.

## Outputs

Each output additionally carries its [output checks](@docroot@/store/derivation/outputs/index.md#output-checks) and whether to [discard its references](@docroot@/store/derivation/outputs/index.md#unsafe-discard-references):

```ebnf
outputs-v2     = list(output-v2) ;
output-v2      = "(" output-name "," output-fields ","
                 output-checks "," unsafe-discard-references ")" ;

output-checks  = "(" allowed-references "," allowed-requisites ","
                 disallowed-references "," disallowed-requisites ","
                 max-size "," max-closure-size "," ignore-self-refs ")" ;

allowed-references    = optional(references) ;
allowed-requisites    = optional(references) ;
disallowed-references = references ;
disallowed-requisites = references ;
max-size              = optional(natural) ;
max-closure-size      = optional(natural) ;
ignore-self-refs      = bool ;

unsafe-discard-references = bool ;

references = list(reference) ;
| '("path",' deriving-path ")" ;
```

Checks are always given per output.
Checks that should apply to all outputs alike are repeated for each.

A `reference` is as in [interpolated strings](#interpolated): one of the derivation's own outputs, or one of its inputs.

An input-addressed output's `output-path` is set exactly when its path can be computed by [static speculation](@docroot@/store/derivation/outputs/input-address.md#static), and is then the path so computed; otherwise it is empty, and the output is [deferred](@docroot@/store/derivation/outputs/input-address.md#deferred).
A reader recomputes it, and rejects a derivation that records a different path, or leaves out one that could be recorded.

## Input derivations

Version 2 derivations may have [higher-order inputs](@docroot@/store/derivation/index.md#dynamic), so a node always has the nested form, naming outputs of the input derivation and, recursively, outputs of derivations that are themselves its outputs:

```ebnf
input-drvs-v2 = list(input-drv-v2) ;
input-drv-v2  = "(" drv-path "," input-drv-node-v2 ")" ;

input-drv-node-v2 = "(" output-names "," list(child) ")" ;
child             = "(" output-name "," input-drv-node-v2 ")" ;
```

A non-empty list of children requires the [`dynamic-derivations`][xp-feature-dynamic-derivations] experimental feature.
A node must name at least one output, or have at least one child.

## Environment variables

Each environment variable carries its *pass as file* flag, and its value is [interpolated](#interpolated):

```ebnf
env-v2       = list(env-entry-v2) ;
env-entry-v2 = "(" string "," interpolated "," bool ")" ;
```

There are no [structured attributes](@docroot@/store/derivation/index.md#structured-attrs), so the `__json` environment variable has no special meaning.
Nor do the environment variables that encode options and *pass as file* flags in version 1 derivations, such as `passAsFile`: version 2 derivations have the options and flags themselves.

## Options

The [options](@docroot@/store/derivation/index.md#options) that apply to the derivation as a whole:

```ebnf
options = "(" export-references-graph "," required-system-features ","
          prefer-local-build "," allow-substitutes "," impure-env-vars ","
          no-chroot "," additional-sandbox-profile "," impure-host-deps ","
          allow-local-networking ")" ;

export-references-graph    = list(export) ;
export                     = "(" string "," list(deriving-path) ")" ;
required-system-features   = list(string) ;
prefer-local-build         = bool ;
allow-substitutes          = bool ;
impure-env-vars            = list(string) ;
no-chroot                  = bool ;
additional-sandbox-profile = string ;
impure-host-deps           = list(string) ;
allow-local-networking     = bool ;
```

## Leaves

```ebnf
optional(x)   = "[" [ x ] "]" ;
bool          = '"false"' | '"true"' ;
natural       = '"' digit { digit } '"' ;   (* no leading zeros *)
deriving-path = string ;
```

`optional(x)` is, like [`list(x)`](../derivation-aterm.md#combinators), a macro: a list of at most one element, empty when the value is absent.
A `deriving-path` is written in its [encoding](@docroot@/store/derivation/index.md#deriving-path-encoding), with `^` separators.

Every field is always present, even when it has its default value, so that each version 2 derivation has exactly one encoding.
The rules of [canonical form](../derivation-aterm.md#canonical-form) apply; in particular, every list representing a set or a map is in ascending order of its elements' or keys' encodings, with no duplicates.
